Orientation

How a model learns

Before any model name matters, there is a prior question: what did the machine have to learn from? The answer splits all of machine learning into five paradigms. Every algorithm later in this file belongs to one of them.

Supervised learninglabelled data

You give the machine examples that already carry the right answer. It learns the relationship between the inputs and that answer, so it can answer new cases.

The shape of it paradigm

Rows in, one known answer column, learn the mapping.

ExampleYou have 50,000 past insurance claims. For each one you already know whether it turned out to be fraudulent. You hand the machine all 50,000 rows with the fraud yes/no column. It learns which combinations of claim amount, time since policy start, and repair shop tend to go with fraud. Tomorrow a new claim arrives with no answer attached, and the model gives you one.

Recognise it by: someone had to sit down and label the training data, or history supplied the labels for free (the sale either happened or it didn't).

Unsupervised learningno labels

No answers exist. The machine looks for structure that is already sitting in the data and tells you what it found.

The shape of it paradigm

Rows in, no answer column, get back groups, rules, or a simplified version of the data.

ExampleSame insurer, different question: nobody has ever categorised their customers. You hand over the 50,000 rows with no labels at all and ask the machine to group customers that resemble each other. It comes back with four groups. Looking at them you realise group 3 is "young drivers with expensive cars who claim often". Nobody told the machine that category existed, it was implied by the data.

Recognise it by: there is no right answer to check against. You judge the result by whether it is useful, not by whether it is correct.

Semi-supervised learninga few labels

A small labelled pile and a huge unlabelled one. The model uses the small pile to make sense of the big one.

The shape of it paradigm

Labelling is expensive, so label a little and let the model exploit the rest.

ExampleA hospital has 100,000 chest X-rays but only 500 have been read and annotated by a radiologist, because that costs real specialist hours. A semi-supervised model learns from the 500, makes guesses on the other 99,500, keeps only the guesses it is very confident about, and retrains on the expanded set.

Recognise it by: the phrase "labelling is expensive" is always somewhere in the problem statement.

Self-supervised learninglabels from the data itself

Nobody labels anything, but the data generates its own answers by hiding part of itself. This is how every large language model is trained.

The shape of it paradigm

Cover up part of the input and make the model reconstruct it. The hidden part is the label.

ExampleTake the sentence "the truck parked outside the stadium". Hide the last word and ask the model to predict it. The correct answer was already sitting in the text, so no human had to write it down. Do this a trillion times across the internet and the model ends up with a working model of language. That is literally how Gemini and every other LLM is pre-trained.

Recognise it by: a task invented purely to create labels out of unlabelled data. It looks unsupervised from the outside and supervised from the inside.

Reinforcement learningrewards, not answers

No dataset of right answers. An agent acts, the environment scores it, and it adjusts to earn more points next time.

The shape of it paradigm

Try something, see the consequence, get better. Learning by trial and error, formalised.

ExampleA warehouse robot must get from the door to a shelf. Nobody has a dataset of correct routes. The robot moves, and the environment gives it points: −1 for every second elapsed, −100 for hitting a wall, +50 for reaching the shelf. After thousands of attempts it has learned a route nobody wrote down. The key difference from supervised learning: nobody ever told it the correct move, only whether things went well afterwards.

Recognise it by: a sequence of decisions where the consequences arrive later, and the words "reward", "agent", "environment", "policy".

The workhorse

Supervised learning

The workhorse of business machine learning. It splits cleanly in two, and the split is decided by one question only: is the thing you are predicting a number, or a category?

A number to predict means regression. A category to predict means classification. Same algorithms often do both (a decision tree will happily do either), but the problem type decides the metric you judge it by and the version of the algorithm you use.
Regression, predicting a number9 models

The output is a continuous quantity: dollars, hours, degrees, counts. "How much" or "how many".

Linear regression the baseline

Draws the single straight line that best fits the data, then reads predictions off that line.

ExampleYou have 300 houses with their floor area and selling price. Linear regression finds one formula, price = 180,000 + 240 × square feet. A new 1,500 sq ft house is predicted at 180,000 + 360,000 = $540,000. Every extra square foot is worth exactly $240, always, regardless of anything else. That rigidity is both its weakness and why anyone can read the result.

Start here always. If a fancier model can't beat a linear regression by a worthwhile margin, ship the linear regression. You can explain it to a finance director in one sentence.

Polynomial regression curved line

The same idea, but the line is allowed to bend.

ExampleIce cream sales against temperature. From 10°C to 30°C sales climb steeply, but above 35°C people stay indoors and sales flatten and fall. A straight line can't represent "rises then falls", a curve can. Polynomial regression fits that arch.

The danger: allow enough bends and the curve will thread perfectly through every training point and be useless on new ones. That is overfitting in its most visual form.

Ridge, Lasso, Elastic Net regularised

Linear regression with a penalty that punishes the model for leaning too hard on any one input.

ExampleYou predict employee attrition risk from 200 HR columns. Plain linear regression latches onto noise, it decides "badge number" matters. Ridge shrinks every coefficient toward zero, so no single column dominates. Lasso goes further and pushes weak coefficients to exactly zero, effectively deleting those columns; you end up with 12 columns that matter out of 200. Elastic Net is both penalties combined.

Lasso is a feature selector. When you hear "the model chose its own features", it is usually Lasso.

Decision tree regressor rules

A flowchart of yes/no questions. Each leaf of the tree holds an average value.

ExamplePredicting a used car's price. The tree asks: is it older than 8 years? Yes → is the mileage over 150,000? Yes → predict $3,200 (the average of all training cars that landed in that leaf). It is a series of splits, not a formula, so there is no single "per mile" rate, because the relationship can change shape in each branch.

Fully readable. You can print the tree and hand it to a person. One tree on its own is usually weak; its value is as a building block for forests and boosting.

Random forest regressor bagging

Hundreds of decision trees, each trained on a random slice of the rows and columns. Their predictions get averaged.

ExampleForecasting monthly spare parts demand. One tree might fixate on a single odd month in the training data. Build 500 trees, each seeing a different random two-thirds of the rows and a random subset of columns, and average them, the individual quirks cancel out and what survives is the real signal. Almost always better than any single tree.

Trees are built independently and in parallel. That is the difference from boosting, below.

Gradient boosted trees, XGBoost, LightGBM, CatBoost the tabular champion

Trees built one after another, where each new tree specialises in fixing the errors the previous ones made.

ExamplePredicting customer lifetime value. Tree 1 predicts $400 for everyone and is badly wrong for high spenders. Tree 2 is trained not on the value but on tree 1's mistakes, and learns "add $600 when the customer has more than 3 orders". Tree 3 corrects what remains. After 500 rounds of this the combined model is far sharper than any single tree. XGBoost, LightGBM and CatBoost are three implementations of this idea. LightGBM is the fastest on wide data, CatBoost handles text-like categorical columns best.

The default winner on spreadsheet-shaped data. For rows and columns, which is most business data, boosted trees usually beat neural networks. Neural networks win on images, audio and text.

Support vector regression (SVR) tube fitting

Fits a tube around the data and only penalises points that fall outside it.

ExamplePredicting machine temperature from 40 sensor readings, where you genuinely don't care about errors under 2°C. SVR draws a band of tolerance and ignores everything inside it, concentrating entirely on the points that miss badly. Strong when you have many columns and relatively few rows.

k-nearest neighbours regressor lazy

Doesn't learn anything up front. When asked, it finds the k most similar past rows and averages their answers.

ExamplePricing a flat. Find the 5 most similar past sales (similar size, floor, postcode) and average their prices. That is the entire algorithm. Nothing is "trained"; the whole dataset is the model, which is why it is called a lazy learner.

Breaks down with many columns. With 200 columns everything is roughly equally far from everything else, and "nearest" stops meaning anything. That is the curse of dimensionality.

Neural network regressor learned features

Layers of weighted connections that learn their own intermediate representations before producing a number.

ExamplePredicting energy demand for a city from weather, calendar, satellite cloud imagery and social event feeds all at once. A neural network can consume mixed and unstructured inputs and learn its own internal combinations of them. On a plain table of 30 numeric columns, boosted trees would usually beat it with far less effort.

Classification, predicting a category8 models

The output is a class label: yes/no, spam/not spam, one of twelve product categories. "Which one".

Three sub-shapes worth naming. Binary = two possible answers (fraud or not). Multiclass = one answer from many (which of 8 defect types). Multi-label = several answers can be true at once (this news article is about both Politics and Economics).

Logistic regression the baseline

Despite the name, this is a classifier. It outputs a probability between 0 and 1, which you then cut at a threshold.

ExampleWill this customer churn next month? The model returns 0.82. With a 0.5 cut-off you label them "will churn". Raise the cut-off to 0.9 and you flag fewer people but are more often right about them. The output is a probability, and moving the threshold is a business decision, not a modelling one.

The name is a trap. Logistic regression does classification. Linear regression does regression.

Naive Bayes probability counting

Counts how often each feature appeared with each class, then multiplies the probabilities together.

ExampleSpam filtering. In your training emails the word "invoice" appeared in 3% of legitimate mail and 40% of spam. Multiply that evidence across every word in a new email and you get a spam probability. It is called "naive" because it pretends the words are independent of each other, "free" and "money" are treated as unrelated, which is obviously false, and yet it still works remarkably well and trains in seconds.

k-nearest neighbours classifier lazy

Find the k most similar past rows and take a majority vote of their labels.

ExampleA new support ticket arrives. Find the 7 most similar past tickets; 5 of them were routed to Networking and 2 to Hardware. Route it to Networking. No training step at all.

Decision tree classifier rules

A flowchart of questions ending in a class label rather than a number.

ExampleLoan approval. Is income above $50k? Yes → is existing debt below $20k? Yes → approve. It produces a rule you can print, audit, and defend to a regulator, which is exactly why regulated industries keep using trees even when a black-box model would score slightly better.

Random forest classifier bagging

Many trees, each on a random slice, voting on the class.

ExampleClassifying network traffic as normal or intrusion. 300 trees each see a different random subset of the connection logs and each votes; the majority wins. Robust, hard to overfit, and it hands you a feature importance ranking for free, you can see that packet size mattered more than time of day.

Gradient boosted trees (classification) the tabular champion

Sequential trees, each correcting the errors of those before it, ending in a class probability.

ExamplePredicting which of 200,000 customers will respond to a campaign. The first trees get the easy cases right; later trees spend their effort on the hard, ambiguous customers the earlier ones got wrong. This is the model that wins most tabular data competitions.

Support vector machine (SVM) boundary drawing

Finds the boundary that separates the classes with the widest possible margin between them.

ExampleSeparating two grades of steel from 60 lab measurements each. SVM doesn't care about points far inside their own group, only about the borderline cases near the frontier, the "support vectors". With the kernel trick it can also draw curved boundaries by mathematically projecting the data into a higher dimension where a straight boundary works.

Strong on small, wide datasets: few rows, many columns. Slow and memory-hungry on very large datasets.

Neural network classifier learned features

Layers that learn their own representation of the input before assigning a class.

ExampleDeciding whether a photo of a weld contains a crack. Nobody can write down the rule for "looks cracked" as columns in a table, so the network learns its own internal features, edges, then textures, then crack-shaped patterns, directly from the pixels.

Finding structure

Unsupervised learning

No answers anywhere. Four distinct jobs live here, and they are genuinely different jobs, grouping rows, shrinking columns, finding co-occurrence rules, and spotting the odd one out.

Clustering, grouping similar rows5 models

Put rows into groups where members resemble each other more than they resemble outsiders. The groups have no names until a human looks at them and invents one.

k-means the default

You state how many groups you want (k). It places k centre points and shuffles them until each row belongs to its nearest centre.

ExampleSegment 40,000 retail customers on spend, visit frequency and basket size. You ask for k=4. The algorithm returns four groups; you inspect them and name them yourself: "weekly small baskets", "monthly big shops", "lapsed", "high value". The machine found the boundaries. The names are entirely your interpretation.

You must choose k in advance, which is its main annoyance. It also assumes groups are roughly round and similarly sized.

Hierarchical clustering nested

Builds a tree of groups, every row starts alone, then the closest pair merges, repeatedly, until everything is one group.

ExampleGrouping 80 product SKUs by sales pattern. The output is a dendrogram, a tree diagram. Cut it high and you get 3 broad families; cut it low and you get 15 fine-grained ones. You decide the number of groups after seeing the structure, which is the advantage over k-means.

DBSCAN density based

Groups are dense regions of points. Anything in a sparse region is labelled noise and put in no group at all.

ExampleClustering GPS pings from delivery vans to find genuine stopping locations. Dense clumps of pings are real stops. A handful of scattered pings on a motorway are noise, and DBSCAN says so instead of forcing them into a group. It also finds long, snaking shapes that k-means cannot, because it never assumes a group is round.

The only clusterer here that can say "this point belongs to nothing". You don't tell it how many groups to find.

Gaussian mixture model (GMM) soft grouping

Like k-means, but each row gets a probability of belonging to each group rather than being assigned to exactly one.

ExampleCustomer segmentation where a person is genuinely 70% "bargain hunter" and 30% "premium buyer". k-means would force them into one bucket and lose that. A GMM keeps both numbers, which matters if you are going to target them with messaging.

Mean shift peak seeking

Walks points uphill toward the densest nearby region; wherever many points converge becomes a group.

ExampleFinding the distinct colour regions in an image for compression. You don't say how many colours; the algorithm discovers the natural peaks in the colour distribution.

Dimensionality reduction, shrinking columns5 methods

Take many columns and produce fewer, keeping as much of the information as possible. Used to speed up models, to remove redundancy, and to make data drawable in two dimensions.

This is the one family here that is a preparation step rather than an answer. It produces better inputs for another model, or a picture for a human. It does not predict anything by itself.

Principal component analysis (PCA) the default

Finds new combined axes that capture the most variation, and lets you keep only the first few.

ExampleA fitness dataset with height, weight, chest, waist, hip, shoe size and arm length. These seven columns mostly say one thing, overall body size, with a second, weaker theme of build shape. PCA replaces them with two new columns: "component 1" (size) and "component 2" (shape). You dropped 5 columns and kept nearly all the information. The cost: "component 1" is a blend, so it has no plain-English name any more.

Linear only. It can only build straight-line combinations of your existing columns.

t-SNE for pictures

Squashes many dimensions down to two for plotting, preserving which points were near each other.

ExampleYou have 5,000 support tickets each converted into a 768-number embedding. Plotting 768 dimensions is impossible. t-SNE maps them to an x,y scatter plot where similar tickets sit together, and you can see with your eyes that there are five topic islands.

For looking, not for feeding. Distances between the resulting clusters are not meaningful, and it is slow. Never use its output as input to another model.

UMAP for pictures, faster

Same purpose as t-SNE, faster, and better at preserving the large-scale structure as well as the local.

ExampleThe same 5,000 tickets, but now 5 million log entries. t-SNE would take hours; UMAP handles it and keeps the relationships between the big clusters more faithfully. It has largely displaced t-SNE as the default choice.

SVD / matrix factorisation decomposition

Breaks one big table into a product of smaller ones that approximately reconstruct it.

ExampleA grid of 100,000 users by 20,000 films, almost entirely empty because nobody watches 20,000 films. SVD decomposes it into user preferences over ~50 hidden themes and film scores on those same themes. Multiply the two back together and you get a prediction for every empty cell. That is a recommendation engine.

Autoencoder neural, non-linear

A neural network trained to squeeze input through a narrow middle layer and reconstruct it on the other side. The narrow layer is the compressed version.

ExampleFeed 200 sensor readings from a turbine into a network that funnels them down to 10 numbers, then expands back to 200. If the output closely matches the input, those 10 numbers captured the essentials. Bonus use: when a new reading reconstructs badly, something unprecedented is happening, which makes an autoencoder a working anomaly detector.

The non-linear PCA. It can learn curved relationships PCA cannot. Available in BigQuery ML.

Association rule learning, what goes with what3 algorithms

Finds items that show up together more often than chance would explain. Classically called market basket analysis.

Apriori the classic

Counts item combinations, discarding any combination too rare to matter before extending it.

ExampleAcross 2 million supermarket receipts it finds: of baskets containing nappies, 34% also contain beer, which is four times the rate of beer in baskets overall. The rule is "nappies → beer". Three numbers define it: support (how often the combination appears at all), confidence (how often B appears given A), lift (how much more often than chance). Lift above 1 means a real association.

Correlation, never causation. The rule does not say buying nappies causes beer purchases, only that they travel together.

FP-Growth faster

The same output as Apriori, but it compresses the transactions into a tree first instead of repeatedly rescanning them.

ExampleThe same 2 million receipts. Apriori passes over the data once per combination size and gets slow. FP-Growth builds one compact tree and reads the rules out of it, typically an order of magnitude faster. Same rules, better engineering.

Eclat set intersection

Stores, for each item, the list of transactions containing it, and intersects those lists.

ExampleTo test "bread and butter", intersect the set of receipts containing bread with the set containing butter. The size of the overlap is the support. Efficient when the data is a long thin list of transaction IDs.

Anomaly detection, finding the odd one out4 methods

Identify records that don't resemble the rest. Usually unsupervised, because by definition you rarely have enough labelled examples of the rare thing.

Isolation Forest the default

Splits data randomly and measures how few splits it takes to isolate each point. Weird points isolate quickly.

Example1.2 million card transactions. A $4 coffee sits in a dense crowd of similar transactions and takes many random splits to separate out. A $9,400 purchase at 4am in a foreign country gets isolated in two or three splits. Fewer splits means more anomalous. That is the entire scoring mechanism, and it is fast on large data.

Useful for security logs: the same logic flags the login that doesn't resemble any other login.

One-class SVM boundary

Learns a boundary around what normal looks like. Anything outside it is anomalous.

ExampleTrain only on 6 months of healthy pump vibration readings. The model draws a envelope around normal. When a reading falls outside that envelope, the pump is behaving in a way it never has before, even though you have never seen a failure and so could never have labelled one.

Local outlier factor (LOF) relative density

Compares a point's local crowding to the crowding of its neighbours. Being in a sparse spot only counts as odd if the neighbours are in dense spots.

ExampleRural and urban stores have naturally different footfall density. A quiet rural store isn't an anomaly because its neighbours are also quiet. A quiet store surrounded by busy ones is. LOF captures "odd relative to your own neighbourhood", which a global method misses.

Autoencoder reconstruction error neural

Train to rebuild normal data. Whatever rebuilds badly is abnormal.

ExampleReconstruct network flow records. Ordinary HTTP traffic rebuilds almost perfectly. A novel exfiltration pattern the network has never encountered rebuilds with large error, and that error is the anomaly score.

Cheap labels

Semi-supervised and self-supervised

Two ways around the fact that labelling data by hand is slow and expensive. The second one turned out to be the foundation of every modern language model, which is why it is worth more than a footnote.

Semi-supervised techniques3 methods

Self-training / pseudo-labelling bootstrapping

Train on the few labels, predict the rest, keep the confident predictions as if they were real labels, retrain.

Example500 support tickets categorised by hand out of 50,000. Train on the 500. Predict the other 49,500 and keep only the ~8,000 predicted with over 95% confidence. Retrain on 8,500 rows. Repeat. The risk is obvious and real: an early mistake gets treated as truth and compounds.

Label propagation spreading

Build a graph connecting similar rows and let labels flow along the connections.

ExampleThree known fraudulent accounts in a network of transfers. Accounts heavily connected to those three inherit some fraud suspicion, which then spreads onward with diminishing strength. The label seeps through the network rather than being predicted row by row.

Co-training two views

Two models look at different halves of the features and teach each other.

ExampleClassifying web pages. Model A reads only page text, model B reads only inbound link text. When A is confident about a page B finds unclear, A's answer becomes a training label for B, and vice versa. Each teaches the other using evidence the other couldn't see.

Self-supervised techniques3 methods

The machine manufactures its own labels by hiding part of the data. This is the engine behind foundation models.

Next-token prediction how LLMs are built

Given the text so far, predict the next chunk. Repeat across enormous volumes of text.

Example"The invoice was approved by the finance ___". The correct answer, "team", was already in the source document, so no annotation was needed. Doing this across trillions of words forces the model to learn grammar, facts, and reasoning patterns as a side effect of getting good at the guess. Gemini, Claude and GPT are all trained this way.

Masked language modelling BERT style

Blank out random words in the middle and predict them using context from both sides.

Example"The [MASK] rejected the claim because the policy had lapsed." The model sees the words before and after, which makes it strong at understanding text but not at generating it left to right. This is why BERT-family models are used for search, classification and embeddings rather than chat.

The split that explains the model zoo: masked models understand (encoders), next-token models generate (decoders).

Contrastive learning, SimCLR, CLIP same or different

Show pairs and train the model to pull matching things together and push mismatched things apart.

ExampleCLIP is shown 400 million image-and-caption pairs from the web. It learns to place a photo of a dog and the words "a photo of a dog" at nearly the same spot in a shared mathematical space. No one labelled anything. The pairing itself was the supervision. This is why you can now search images by typing a description.

Learning by consequence

Reinforcement learning

An agent takes actions in an environment and receives rewards. There is no dataset of correct answers, only consequences. The vocabulary is fixed and worth learning once. Agent is the decider, environment the world it acts in, state the situation right now, action what it does, reward the score it gets back, policy its strategy for choosing.

Value-based methods2 models

Learn how much each situation-and-action is worth, then always pick the most valuable action.

Q-learning table of values

Builds a table: for each state, the expected long-run reward of each possible action.

ExampleA lift controller. State = which floors have waiting passengers and where the car is. Action = up, down, or hold. After thousands of simulated days the table contains entries like "car on floor 3, calls waiting on 7 → going up is worth 14.2 points, holding is worth 2.1". It then just reads off the best action. Works only when the number of states is small enough to enumerate.

Deep Q-Network (DQN) neural table

Replaces that table with a neural network, so the state can be something huge like a screen of pixels.

ExampleDeepMind's Atari agents. The state is the raw screen image, far too many possible states to tabulate, so a network estimates the value of each joystick action from the pixels. The agent learned to play Breakout from nothing but the score.

Policy-based and actor-critic4 models

Instead of scoring every action, learn the strategy directly.

REINFORCE / policy gradient direct strategy

Adjust the strategy so actions that preceded good outcomes become more likely.

ExampleA robot arm learning to pour. Rather than scoring every possible wrist angle, it nudges the probabilities of the movements it just made up or down depending on whether liquid ended up in the glass. Necessary when actions are continuous, a wrist angle has infinite possible values, so there is no table to build.

PPO, Proximal Policy Optimization the workhorse

Policy gradient with a safety clamp that prevents any single update from changing the strategy too drastically.

ExamplePlain policy gradients can catastrophically overcorrect after one lucky episode and destroy weeks of learning. PPO limits how far the new strategy may move from the old one per update. It is stable enough to be the default in robotics, and it is the algorithm used to fine-tune chatbots on human feedback.

Actor-critic, A3C, SAC two networks

One network chooses actions (actor), a second judges how good the situation is (critic), and the critic's judgement trains the actor.

ExampleAn autonomous drone. The actor picks thrust and tilt. The critic estimates how promising the current position is. Instead of waiting until the flight ends to learn anything, the actor gets feedback at every step from the critic. Far faster learning than waiting for the final reward.

Model-based RL, AlphaZero, MuZero plans ahead

The agent learns a model of how the environment behaves and simulates futures before acting.

ExampleAlphaZero plays chess by internally simulating candidate continuations many moves deep, guided by a network that evaluates positions, rather than reacting move by move. MuZero goes further and learns the rules of the game itself from experience without ever being told them.

RLHF, where RL meets language models1 method

Reinforcement learning from human feedback alignment

Humans rank model outputs; those rankings train a reward model; the language model is then optimised against that reward.

ExampleA raw LLM trained only on next-token prediction will happily continue a question with more questions, because that is what text on the internet does. Humans are shown pairs of answers and pick the better one. Those preferences train a reward model, and PPO then tunes the LLM to score well against it. This step is what turns a text-continuation engine into an assistant that answers you.

This is the bridge between the RL section and the generative AI section. Worth remembering that the two halves of this file meet here.

Combining models

Ensembles

Not a model type, but a strategy for combining models. It cuts across everything above, and it is why random forests and XGBoost, the two most-used tabular models in industry, work as well as they do.

The four combination strategies4 methods

Bagging parallel, independent

Train many copies of the same model on different random samples of the data, then average or vote.

ExampleAsk 500 analysts to forecast next quarter, each given a different random two-thirds of the history. Individually some will be badly wrong in different directions; the average is steadier than any one of them. Random forest is bagging applied to decision trees. The models never see each other and can be trained in parallel.

Fixes variance, meaning models that are individually erratic.

Boosting sequential, corrective

Train models one after another, each focused on what the previous ones got wrong.

ExampleAnalyst 1 makes a forecast. Analyst 2 is given only analyst 1's errors and told to predict those. Analyst 3 predicts what's still wrong after 1 and 2. Sum all their outputs. XGBoost, LightGBM and CatBoost are all boosting. Cannot be parallelised across models, because each one needs the previous one's mistakes.

Fixes bias, meaning models that are consistently, systematically off. This is the single most useful distinction in the section: bagging is parallel and averages away noise, boosting is sequential and chases errors.

Stacking a model of models

Run several different model types, then train a final model whose inputs are their predictions.

ExampleA random forest, a logistic regression and a neural network each predict churn probability. A small final model learns that the forest is more reliable for long-tenure customers while the neural net is better for new ones, and weights them accordingly per case. The combiner learns when to trust whom.

Voting / averaging the simple one

Take several finished models and just average their outputs, or take a majority vote.

ExampleThree fraud models you already have in production. Flag a transaction when at least two say fraud. No extra training, no combiner model, often a worthwhile accuracy gain for an afternoon of work.

Architectures

Deep learning architectures

A neural network is layers of simple units, each passing weighted numbers to the next, with the weights adjusted until output matches target. "Deep" just means many layers. What distinguishes the architectures below is how the layers are wired, and each wiring suits a different shape of data.

Deep learning is not a separate paradigm. A neural network can be supervised, unsupervised, self-supervised or reinforcement-driven. It is a family of model shapes, orthogonal to how it learns.
Foundational architectures4 types

Feedforward network / MLP the plain one

Every unit in a layer connects to every unit in the next. Data flows one way, input to output.

ExamplePredicting loan default from 30 numeric columns. 30 inputs → a layer of 64 units → a layer of 32 → one output between 0 and 1. It knows nothing about ordering or position, shuffle the columns and it learns equally well, which is exactly why it is wrong for images and text where position carries meaning.

Convolutional neural network (CNN) grids and images

Slides small filters across the input so that the same pattern is recognised anywhere it appears.

ExampleDetecting a crack in a weld photo. A small filter learns "edge", and because the same filter is swept across the whole image, an edge is detected whether it is top-left or bottom-right. Early layers find edges, middle layers find textures, deep layers find crack-shaped things. That reuse is why a CNN needs vastly fewer parameters than an MLP for the same image.

Any data on a grid. Images obviously, but also spectrograms of audio, and sometimes time series treated as a 1-D grid.

Recurrent network, RNN, LSTM, GRU sequences, older

Processes a sequence one step at a time, carrying a memory of what came before.

ExamplePredicting the next value in a stream of sensor readings. The network reads reading 1, updates its memory, reads reading 2, and so on. Plain RNNs forget quickly over long sequences; LSTM adds gates that decide what to keep and what to discard, and GRU is a lighter version of the same idea. Largely superseded by transformers for text, still used for modest time-series work.

Strictly sequential, which means it cannot be parallelised across the sequence. That bottleneck is precisely what transformers removed.

Graph neural network (GNN) networks of things

Works on data shaped as nodes and edges, letting each node gather information from its neighbours.

ExampleFraud rings. The suspicious signal isn't in any single account's columns, it's that these six accounts all transfer to the same two destinations and share a device fingerprint. A GNN lets each account's representation absorb information from its connections, so the ring becomes visible. Also used for molecules, road networks and recommendation graphs.

The transformer and its descendants5 types

The 2017 architecture behind essentially all modern language and multimodal models. Its core trick, attention, lets every position in a sequence look directly at every other position in one step instead of passing information along a chain.

Transformer attention

Each word computes how relevant every other word is to it, and blends them accordingly.

Example"The truck couldn't fit under the bridge because it was too tall." To resolve what "it" refers to, the model computes an attention weight from "it" to every other word; "truck" scores high, "bridge" lower. An RNN would have had to carry that information step by step and might have lost it. Attention reaches across the whole sentence at once, and because every position is computed simultaneously, training parallelises across thousands of chips.

The cost: comparing every position to every other means work grows with the square of the sequence length. That is why context windows were historically limited and why the alternatives below exist.

Encoder-only, BERT family understanding

Reads the whole input at once, in both directions, and produces a representation. Does not generate text.

ExampleConverting a support ticket into a 768-number embedding that captures its meaning, so you can cluster tickets, search them by similarity, or classify them. Used for search ranking and classification, not for chat.

Decoder-only, GPT, Gemini, Claude generating

Generates one token at a time, each conditioned on everything produced so far.

ExampleYou type a prompt; the model emits "The", then reads its own "The" and emits "invoice", then reads both and emits "was". Every chat model works this way. It can only look backwards, which is what makes generation coherent left to right.

This is the architecture of every model you have actually talked to.

Encoder-decoder, T5, original translation models in one form, out another

One stack reads the input fully, a second stack writes the output.

ExampleTranslation. The encoder reads the entire German sentence and builds a meaning representation; the decoder writes the English sentence from it. Also natural for summarisation, where input and output are different lengths and forms.

Mixture of Experts (MoE) selective activation

The model contains many specialised sub-networks, but each token only activates a couple of them.

ExampleA model holding 400 billion parameters across 64 expert sub-networks, where a router sends each token to only the 2 most suitable experts. You get the knowledge capacity of a huge model at the running cost of a much smaller one. Most current frontier models use this.

Generative architectures4 types

Autoencoder compress and rebuild

Squeeze the input through a narrow layer and reconstruct it. Covered under dimensionality reduction, repeated here because it is the ancestor of the next one.

Example200 turbine sensors compressed to 10 numbers and expanded back. Good reconstruction means the 10 numbers held the essentials.

Variational autoencoder (VAE) compress into a space you can sample

An autoencoder whose middle layer is a smooth probability distribution, so you can pick a random point in it and decode something new.

ExampleTrain on thousands of chair photos. The middle layer becomes a continuous "space of chairs". Pick a point between two chairs and decode it, and you get a plausible chair that never existed. A plain autoencoder's middle layer has gaps, sample it and you get noise.

Generative adversarial network (GAN) forger vs detective

Two networks compete: one generates fakes, the other tries to spot them. Both improve until the fakes pass.

ExampleA generator produces fake faces; a discriminator judges real versus fake. Early on the fakes are obvious blobs. As the discriminator sharpens, the generator is forced to improve, and after many rounds it produces photorealistic faces. Dominant for image generation until roughly 2022, now largely replaced by diffusion, which trains far more stably.

Diffusion model denoising

Learns to remove noise. Start from pure static and repeatedly denoise until an image appears.

ExampleTraining: take a real photo and add noise in 1,000 small steps until it is static; teach the network to reverse one step. Generating: start with pure static and apply that learned reversal 1,000 times, steered by the text prompt, and a photo of the requested subject emerges. Imagen, Stable Diffusion, Midjourney and Veo all work this way.

The current default for images and video. If you remember one thing: diffusion makes pictures, transformers make text, and the newest models combine both.

The newest wing, state space models2 types

Transformers cost grows with the square of sequence length. State space models are the serious attempt at an alternative, and as of 2026 they appear mostly in hybrids rather than replacing transformers outright.

Mamba / selective state space models linear-time sequences

Carries a compact running state through the sequence and selectively decides what to keep, scaling linearly rather than quadratically with length.

ExampleProcessing a 500,000-token document. A transformer must relate every token to every other, and the cost explodes. Mamba maintains a fixed-size state as it reads, so doubling the document roughly doubles the work instead of quadrupling it. It matches similarly-sized transformers on many language benchmarks with lower latency and memory.

Think of it as an RNN that learned the lessons of the transformer era: sequential state, but trainable in parallel and selective about what it remembers.

Hybrid models, Jamba, Granite 4.0, Codestral Mamba both wirings

Interleave attention layers with state space layers to get precise recall and cheap long context together.

ExampleA model where most layers are Mamba blocks handling the bulk of the sequence cheaply, with occasional attention layers where exact lookups matter. As of 2026 this hybrid shape, not pure Mamba, is where state space models actually ship, transformers remain dominant overall.

Making content

Generative AI

Models that produce new content rather than a label or a number. Architecturally these are the transformers and diffusion models from the previous section; what earns them a section of their own is the layer of techniques built around using them.

Model types by what they produce5 types

Large language model (LLM) text

A decoder-only transformer trained on enormous text volumes to predict the next token.

ExampleGemini, Claude, GPT, Llama. Give it a paragraph of meeting notes and ask for action items, and it produces them, not by looking anything up, but by generating the most plausible continuation of "here are the action items:" given everything it learned during training. That is also why it can state something false with complete confidence: plausibility, not verification, is the objective it was trained on.

Text-to-image images

Diffusion models steered by a text prompt.

ExampleGoogle's Imagen. "A coffee truck on a rainy London street at dusk" becomes an image through iterative denoising, where the text embedding steers each denoising step toward matching the description.

Text-to-video video

Diffusion extended across time, so consecutive frames stay consistent.

ExampleGoogle's Veo. The hard part is not any single frame. It is that the truck must stay the same truck from frame 1 to frame 120, with plausible motion. The model denoises across space and time together.

Multimodal model several input types

Accepts text, images, audio and video in the same context and reasons across them.

ExampleUpload a photo of a whiteboard sketch plus a spreadsheet and ask "does this design match these numbers?". The model represents both in the same internal space and answers about the relationship between them. Gemini is natively multimodal: it was trained on mixed modalities rather than bolting an image reader onto a text model.

Embedding model meaning as numbers

Converts text, images or audio into a list of numbers positioned so that similar meanings sit close together.

Example"How do I reset my password?" and "I forgot my login" contain no shared words, but their embeddings land near each other, so a similarity search finds one when you search the other. Embeddings are the quiet infrastructure under semantic search, clustering and RAG. Not generative themselves, but nothing generative works well without them.

Techniques around the model6 methods

You rarely train a foundation model. What you actually do is one of these.

Prompt engineering no training

Change the instructions, not the model.

Example"Summarise this" produces something generic. "Summarise this incident report in 3 bullets for a non-technical executive, leading with business impact" produces something usable. Same model, same weights. Related terms: zero-shot (no examples given), few-shot (two or three worked examples included in the prompt), chain of thought (asking it to reason step by step before answering).

RAG, retrieval augmented generation no training

Search your own documents first, paste the results into the prompt, then let the model answer from them.

ExampleAn internal policy assistant. The model was never trained on your company handbook. When someone asks about parental leave, the system embeds the question, finds the three most similar handbook passages, and puts them into the prompt with "answer using only this". You get current, citable answers without retraining anything, and when the handbook changes, you re-index rather than retrain.

The default answer to "the model doesn't know our data". Cheaper, faster and more auditable than fine-tuning, and it is what most enterprise gen AI projects actually are.

Fine-tuning training

Continue training a pretrained model on your own examples so it adopts a style, format or specialised vocabulary.

ExampleYou need output in a rigid internal ticket format every time. Feed 2,000 examples of input and correctly formatted output, and the model learns the shape. Note what this is good for: behaviour and format. For injecting facts, RAG is usually the better tool.

PEFT and LoRA cheap training

Fine-tune by training a small number of added parameters while the original model stays frozen.

ExampleFully fine-tuning a 70-billion-parameter model means updating all 70 billion, which needs a small datacentre. LoRA freezes them and trains a thin adapter of maybe 20 million parameters, achieving most of the benefit on one machine. You can also keep several adapters and swap them per use case, over one shared base model.

Distillation shrinking

Train a small model to imitate a large one's outputs.

ExampleA large model classifies 500,000 documents beautifully but costs too much to run per request. Use its outputs as training data for a much smaller model. The small one keeps most of the accuracy on that specific task at a fraction of the cost. Most "flash", "mini" and "lite" model variants come from this process.

Quantization shrinking

Store the model's numbers at lower precision so it needs less memory.

ExampleWeights stored as 16-bit numbers converted to 4-bit. The model gets roughly four times smaller and faster with modest accuracy loss. This is what makes it possible to run a capable model on a laptop or a phone.

Agents3 concepts

The step beyond generating text: the model decides on and performs actions.

Tool use / function calling the mechanism

The model is told which functions exist and outputs a structured request to call one, which your code executes and hands back.

ExampleAsked "how many open tickets does Acme have?", the model cannot know. It is given a tool called query_tickets(customer), so it emits a call to it, your system runs the query, returns 14, and the model writes the sentence. The model never queried anything. It decided what to call and interpreted the result.

Agent the loop

A model in a loop: pick an action, observe the result, decide the next action, until the goal is met.

Example"Reconcile last month's invoices." The agent queries the billing system, notices three mismatches, looks each up in the ERP, finds two are timing differences, drafts a note about the third, and stops. Multiple steps, each chosen based on what the previous step returned. The difference from a chatbot is that it acts and then reacts to consequences.

Multi-agent systems several agents

Several specialised agents with different tools and instructions, coordinated toward one goal.

ExampleA research agent gathers sources, a writing agent drafts, a critic agent checks claims against the sources, and a coordinator decides when it is done. Each has a narrow job and its own tools, which keeps any one prompt from having to do everything.

Specialist problems

Specialist families

Problem types with enough distinctive structure that they developed their own methods, sitting slightly outside the clean supervised/unsupervised split.

Time series forecasting5 models

Technically regression, but the rows are ordered in time and depend on each other, which breaks the usual assumption that rows are independent. You also cannot shuffle rows into random train and test splits, you must train on the past and test on the future.

ARIMA the classic

Predicts the next value from a combination of recent values and recent errors, after removing trend.

ExampleMonthly units shipped for three years. ARIMA models the relationship between this month and the previous few months, plus how wrong it was recently, and projects forward. Three parameters: how many past values to use, how much differencing to remove trend, how many past errors to use.

ARIMA_PLUS BigQuery flavour

Google's packaged version that handles seasonality, holidays, missing values and outliers automatically.

ExampleIn BigQuery ML you write CREATE MODEL ... OPTIONS(model_type='ARIMA_PLUS') over a date column and a value column. It detects weekly and yearly seasonality, accounts for public holidays, cleans spikes, and returns a forecast with confidence intervals. ARIMA_PLUS_XREG is the same with extra explanatory columns such as price or temperature.

Worth knowing: this is the forecasting model name in BigQuery ML.

Exponential smoothing / Holt-Winters weighted recency

A weighted average of history where recent observations count more, with separate terms for trend and season.

ExampleHotel occupancy with a strong yearly cycle. The model holds three things, current level, current trend, seasonal pattern, and updates each as new data arrives. Simple, fast, surprisingly hard to beat on short clean series.

Prophet business series

Decomposes a series into trend, seasonality and holiday effects, tolerating gaps and sudden level shifts.

ExampleWebsite traffic with weekly cycles, an annual pattern, Black Friday spikes, and a permanent step up when a big customer signed. Prophet handles those explicitly, and you can tell it about known future events.

Deep forecasting, DeepAR, temporal fusion transformers many series at once

Neural models trained across thousands of related series at the same time so they can share patterns.

ExampleForecasting demand for 50,000 SKUs. A new product has no history of its own, but the model learned typical launch curves from similar products, so it can forecast the new one from day one. Classical methods, which fit each series in isolation, cannot do that.

Recommender systems4 approaches

Collaborative filtering people like you

Recommends based on the behaviour of similar users, ignoring what the items actually are.

ExampleYou and 400 other people all bought the same three power tools. Those 400 also bought a particular workbench, which you haven't. Recommend the workbench. The system knows nothing about what a workbench is, only about the pattern of who bought what.

The cold start problem: a brand-new user or item has no behaviour to match on, so this approach has nothing to work with.

Content-based filtering items like this

Recommends items whose attributes resemble what the user already liked.

ExampleYou watched three documentaries about deep-sea exploration. Recommend another documentary tagged ocean and science. Works for a brand-new item the moment it has attributes, since nobody needs to have interacted with it yet.

Matrix factorisation hidden themes

Decomposes the sparse user-item grid into hidden factors for users and items.

ExampleFrom viewing data alone it discovers latent dimensions that look like "slow-paced", "1980s" and "dialogue-heavy", nobody defined them. Each user gets a score on each dimension and each film does too; multiply to predict the missing ratings. Available directly in BigQuery ML as matrix_factorization.

Two-tower neural retrieval modern

One network embeds users, another embeds items, into the same space; recommendation becomes a nearest-neighbour lookup.

ExampleYouTube-scale recommendation. Embed the user from their history, embed every video once in advance, then find the nearest videos to the user's point. Because item embeddings are precomputed, you can search millions of candidates in milliseconds.

Classic NLP, before transformers3 methods

Still worth knowing: these are cheap, explainable, and often sufficient.

Bag of words counting

Represent a document as counts of each word, discarding all order.

Example"The claim was denied" becomes {the:1, claim:1, was:1, denied:1}. "Denied was the claim" produces exactly the same representation, order is gone entirely. Crude, but enough for many classification tasks and it runs instantly.

TF-IDF weighted counting

Word counts weighted down for words that appear in every document.

ExampleAcross 10,000 insurance documents "policy" appears everywhere and tells you nothing. "Subsidence" appears in 40 documents and is highly informative. TF-IDF scores the rare-but-present words higher. It is still a solid baseline for search and document classification.

Word2Vec / GloVe early embeddings

Assigns each word a vector such that words used in similar contexts land near each other.

ExampleThe famous one: the vector for "king" minus "man" plus "woman" lands near "queen". The limitation that transformers fixed: "bank" gets one single vector, so the riverbank and the financial meaning are blended into one. Transformer embeddings are context-dependent and give each occurrence its own vector.

Computer vision tasks4 tasks

Not models but task definitions. The distinction matters because it decides how you must label your data.

Image classification one label per image

Example"Does this weld photo contain a crack, yes or no?" One answer for the whole image. Labelling means one tick per photo.

Object detection boxes

Example"Find every crack and draw a box around it." Output is a list of boxes with coordinates and labels. Labelling means drawing boxes by hand, dramatically more expensive than classification.

Segmentation per pixel

Example"Mark exactly which pixels are crack." Output is a mask, so you can measure the crack's true area. Labelling means painting the outline by hand, the most expensive of all.

Optical character recognition (OCR) image to text

ExampleReading the invoice number from a scanned PDF. On Google Cloud this is a pretrained API, you never train anything, you call it. Document AI adds structure on top: not just the characters, but which of them is the total.

Vocabulary

The surrounding vocabulary

Terms that appear constantly around every model above. Knowing these is most of what separates following a conversation from guessing at it.

Data and training8 terms

Feature input

ExampleAn input column. Predicting house price, the features are floor area, bedrooms, postcode. In a spreadsheet: every column except the answer.

Label / target answer

ExampleThe column you are predicting. For house price prediction, the price. Only supervised learning has one.

Feature engineering preparation

ExampleCreating better inputs before training. From a raw timestamp you derive "day of week", "is weekend", "hours since last purchase". The model never saw those columns in the source data, you built them because you know they matter. Often worth more than switching algorithms.

Train, validation, test split discipline

ExampleSplit 100,000 rows into 70,000 for training, 15,000 for tuning choices, 15,000 never touched until the very end. The test set exists to answer "how will this do on data it has never seen". Look at it repeatedly while tuning and it stops being able to answer that.

Overfitting the main failure

ExampleA model scores 99% on training data and 61% on new data. It memorised rather than generalised, like a student who learned last year's exam paper by heart. The symptom is always the same: a large gap between training and test performance.

Underfitting the other failure

ExampleA model scores 64% on training data and 63% on new data. Both bad, no gap. The model is too simple for the pattern, a straight line through data that curves.

Hyperparameter your choice

ExampleSettings you pick before training, not learned from data: how many trees in the forest, how many clusters k, the learning rate. Hyperparameter tuning is the search for a good combination, and Vertex AI / Agent Platform automates it.

Cross-validation honest measurement

ExampleSplit into 5 parts, train on 4 and test on the 5th, rotate five times, average the scores. Protects against getting a flattering result purely because of one lucky split. Standard practice when data is limited.

How learning actually happens5 terms

Loss function the scorer

ExampleA number measuring how wrong the model currently is. Predicted $400k, actual $450k, squared error 2.5 billion. Training is nothing more than the search for parameters that make this number small. Choosing the loss function is choosing what "wrong" means.

Gradient descent the method

ExampleWalking downhill in fog. At your position you can feel which direction slopes down; take a step that way; repeat. The landscape is the loss, your position is the parameters. Nearly all model training is this.

Learning rate step size

ExampleHow big each downhill step is. Too large and you stride straight over the valley and bounce between slopes forever. Too small and you take a week to get anywhere. The single most influential hyperparameter in neural network training.

Epoch and batch bookkeeping

ExampleAn epoch is one full pass through the training data. A batch is the chunk processed before updating parameters, 100,000 rows in batches of 256 means 391 updates per epoch. You can't load everything into memory at once, hence batches.

Regularisation restraint

ExampleAny deliberate constraint that stops a model memorising: penalising large coefficients (ridge, lasso), randomly switching off units during training (dropout), or stopping training when validation performance stops improving (early stopping). All of them trade a little training accuracy for real-world accuracy.

Judging a model8 metrics

Different metrics for the two problem types, and the choice matters more than people expect.

Confusion matrix classification

ExampleA 2×2 count of what happened: true positives (flagged fraud, was fraud), false positives (flagged, wasn't), true negatives, false negatives (missed fraud). Every classification metric below is computed from these four numbers.

Accuracy and why it misleads

ExamplePercentage correct. Fraud is 0.2% of transactions, so a model that predicts "never fraud" scores 99.8% accuracy and is worthless. On imbalanced data accuracy is actively misleading. This is the classic trap.

Precision classification

ExampleOf everything you flagged, what fraction was right. You flagged 100 transactions and 80 were genuinely fraud, so precision is 80%. This is the metric that matters when acting on a false alarm is costly, blocking a legitimate customer's card.

Recall classification

ExampleOf everything that truly was fraud, what fraction did you catch. There were 200 frauds, you caught 80, recall is 40%. This is the metric that matters when a miss is costly, an undetected intrusion.

They trade off. Lower your threshold and you catch more fraud (recall up) but flag more innocents (precision down). Choosing the balance is a business decision, not a technical one.

F1 score classification

ExampleOne number combining precision and recall, penalising imbalance between them. Precision 80% and recall 40% gives F1 ≈ 53%, much closer to the weaker of the two than a plain average would be.

ROC-AUC classification

ExampleA single score from 0.5 to 1.0 for how well the model separates the classes across every possible threshold. 0.5 is coin-flipping, 0.9 is strong. Useful when you haven't yet decided where to set the cut-off.

RMSE and MAE regression

ExampleAverage error in the original units. Predicting house prices, RMSE of 30,000 means typically $30k off. RMSE squares errors first, so one $500k miss hurts far more than ten $50k misses. MAE treats all errors proportionally. Pick RMSE when big misses are disproportionately bad.

R squared regression

ExampleThe share of variation the model explains. 0.75 means it accounts for three quarters of the variation in price; the remaining quarter is driven by things not in your data. Unitless, so it is comparable across problems in a way RMSE is not.

Disambiguation

Telling them apart

The distinctions that actually get confused, stated as plainly as possible. If you retain one section, retain this one.

The pairs people mix up10 pairs

Supervised vs unsupervised

The testIs there an answer column in the training data? Yes → supervised. No → unsupervised. Nothing else matters for this call.

Classification vs regression

The testIs the output a category or a number? "Which bucket" → classification. "How much" → regression. Careful: predicting a rating of 1 to 5 stars can legitimately be either, depending on whether you treat the stars as ordered numbers or as five labels.

Linear vs logistic regression

The testLinear predicts a number. Logistic predicts a probability which you turn into a class. The word "regression" in logistic regression is a historical accident.

Bagging vs boosting

The testAre the models built independently and averaged (bagging, random forest), or one after another each fixing the last one's errors (boosting, XGBoost)? Bagging parallelises; boosting cannot.

Clustering vs classification

The testDo the groups already exist and have names? Assigning a ticket to one of your 8 existing categories is classification. Discovering that your customers fall into 4 groups nobody had defined is clustering.

Dimensionality reduction vs feature selection

The testReduction builds new combined columns (PCA makes "component 1" out of seven originals). Selection keeps some originals and drops the rest (lasso zeroes out 188 of 200 columns). After PCA your columns have no plain-English names; after selection they do.

Predictive vs generative AI

The testDoes it output a value or new content? Forecasting next month's sales is predictive. Writing the campaign email about those sales is generative. You will also see predictive AI called "discriminative" or "traditional" AI, same thing.

Fine-tuning vs RAG

The testAre you changing how it behaves or what it knows? Style, tone and output format → fine-tune. Company facts that change over time → RAG. Choosing fine-tuning to inject facts is the most common expensive mistake in enterprise gen AI.

Parameters vs hyperparameters

The testWho set it? Learned from the data during training → parameter (the coefficients, the network weights). Set by you before training → hyperparameter (number of trees, learning rate, k).

Overfitting vs underfitting

The testCompare training score to test score. Big gap, training much better → overfitting, the model memorised. Both scores poor and similar → underfitting, the model is too simple.

Picking a model from the problema short path

The decision path

Walk it in order 1 · Do you have labelled answers? No → unsupervised: grouping rows is clustering, shrinking columns is PCA, finding co-occurrence is association rules, spotting outliers is anomaly detection.

2 · Yes, and the answer is a number → regression. Start with linear regression as a baseline, then try gradient boosted trees.

3 · Yes, and the answer is a category → classification. Start with logistic regression, then gradient boosted trees.

4 · Is the data a plain table of rows and columns? → boosted trees almost certainly win. Don't reach for a neural network.

5 · Is it images, audio, video or free text? → deep learning. CNN for images, transformer for text, diffusion if you need to generate images.

6 · Is it ordered in time? → time series. ARIMA_PLUS in BigQuery, or a deep forecaster if you have thousands of related series.

7 · Do you need new content rather than a prediction? → generative AI. Prompt it first, add RAG if it needs your data, fine-tune only if behaviour needs changing.

The four rungs of AI development4 options

Google frames every AI build as a choice of how much you write yourself. Know this ladder.

1 · Pretrained APIs no code, no training

Someone else's finished model, called over an API. You supply no training data at all.

ExampleVision API to read text from a scanned invoice, Speech-to-Text to transcribe a call, Natural Language API for sentiment. You send input, get output. Choose this when your problem is generic. "read this text" is the same problem for everyone.

2 · AutoML no code, your data

You supply labelled data, Google picks the architecture and trains it.

ExampleClassifying your specific product defects into 8 categories. No pretrained API knows your defect types, so you upload labelled images and AutoML handles the model selection and tuning. Choose it when the problem is specific to you but you have no ML engineers.

3 · BigQuery ML SQL only

Train models with SQL statements, on data already in BigQuery, without moving it anywhere.

ExampleCREATE MODEL churn OPTIONS(model_type='logistic_reg') AS SELECT * FROM customers. The data never leaves the warehouse. For an analyst who knows SQL but not Python, this is the shortest distance from data to a working model, and it is the natural rung for anyone coming from a BI background.

4 · Custom training on Agent Platform full code

Your own code, your own framework, running on managed infrastructure.

ExampleA custom PyTorch architecture trained on TPUs, with your own data pipeline and loss function. Maximum control, maximum effort. Choose it only when the rungs above genuinely cannot do the job.
